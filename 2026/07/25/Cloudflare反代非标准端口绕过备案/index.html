Cloudflare DNS Only：非标准端口直连与可信 HTTPS

发表于 2026-07-25 更新于 2026-07-28

将 Cloudflare 橙色云改为灰色云 DNS Only，让客户端直连源站，可减少跨境代理延迟。直连后浏览器会直接校验源站证书，所以必须先把自签名证书换成 Let’s Encrypt 证书。

非标准端口不等于免除备案义务。请遵守当地法规、云厂商政策和服务条款。

原理

证书绑定域名，不绑定端口，因此可信证书可正常用于 8443。多个服务可以共用该端口，但每个域名都应有独立的 Nginx server 块和证书。

严格按此顺序操作：签发证书 → 修改 Nginx → 直连验证 → DNS Only。

4. 切换前直连验证

保留橙色云，用 --resolve 绕过 Cloudflare 测试源站。不要添加 -k，否则证书验证无效。

只有同时满足以下条件才能继续：

  • remote 等于刚才填写的源站地址。
  • TLS=0，表示浏览器信任链验证成功。

接口返回 401 等鉴权状态不代表证书失败；验证重点是 TLS=0。

5. 切换 DNS Only

进入 Cloudflare Dashboard → 目标 Zone → DNS → Records，修改对应记录：

类型 名称 内容 Proxy status
A <子域名前缀> <源站公网 IPv4> DNS only

将橙色云点成灰色云。源站没有公网 IPv6 时，应删除该域名下手动创建的 AAAA 记录，避免客户端优先连接错误地址。

DNS Only 后，Cloudflare 的 SSL 模式、CDN、WAF 和 Authenticated Origin Pulls 均不再生效。不要启用 Origin Pull 验证，也不要把 8443 限制为仅允许 Cloudflare IP，否则浏览器无法直连。

排错与回滚

现象 检查项
超时 安全组、系统防火墙、是否仍只允许 Cloudflare IP
TLS 不是 0 Nginx 是否仍使用自签名证书、证书路径是否匹配；不要用 -k
remote 不是源站地址 记录仍为橙色云，或本地 DNS 缓存未更新
502 本地后端服务及 proxy_pass 端口
401 通常是应用鉴权响应，与证书无关

需要回滚时，把 DNS 记录切回橙色云。DNS Only 会公开源站地址，并失去 Cloudflare 代理防护；优点是请求不再绕经跨境代理。

访问地址仍需保留 :8443。若要省略端口，必须让 Nginx 监听标准 HTTPS 端口，并先处理端口占用问题。
