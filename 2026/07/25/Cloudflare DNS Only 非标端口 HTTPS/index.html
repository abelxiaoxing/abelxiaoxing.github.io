Cloudflare DNS Only：非标端口直连可信 HTTPS（含 frp 内网穿透）

发表于 2026-07-25 更新于 2026-10-26

国内云厂商对未备案域名的拦截集中在 80/443，非标端口通常不受影响。将 Cloudflare 设为 DNS Only（灰云），让浏览器直连源站的非标端口，再用 DNS-01 签发 Let’s Encrypt 证书，即可在未备案的情况下提供可信 HTTPS。

DNS Only 不是 Cloudflare 反代：橙云（Proxied）才会转发流量，灰云只负责解析。

按应用位置分为两种形态： - 形态 A：应用与 Nginx 都在云服务器上。 - 形态 B：应用在 NAT 后的内网机器上，通过 frp 穿透。frp 基础可参考《frp内网穿透搭建教程》。

两种形态的证书与公网 Nginx 配置基本相同，操作顺序为：接入 Cloudflare → 签发证书 → 配置 Nginx（形态 B 再配 frp）→ 验证 → 确认 DNS。

一、为什么选择 DNS Only？

橙云（Proxied） 灰云（DNS Only，本文）
浏览器连接 Cloudflare 边缘 直连源站
HTTPS 端口 443、2053、2083、2087、2096、8443 任意端口
源站证书 Origin CA 或自签即可 必须是浏览器信任的证书
源站 IP 隐藏 公开
上传、流式输出、WebSocket 受 Cloudflare 限制 由源站自行控制
国内访问 延迟可能波动 通常更稳定

灰云适合需要任意端口、流式传输或端到端控制的场景；代价是源站 IP 暴露，需要自行配置证书和防火墙。

三、准备

先在当前终端设置变量（替换为自己的值），后文命令会自动展开 $DOMAIN 等变量；变量仅在当前终端有效，新窗口需重新设置。

1. 接入 Cloudflare 并配置解析

打开 Cloudflare 控制台，通过 Add a site 添加主域名，再按提示在域名注册商处把 NS 修改为 Cloudflare 分配的两个服务器（官方接入教程）。等待 Zone 状态变为 Active，这是后续 DNS-01 签发证书的前提。

进入 DNS → Records，添加需要访问的子域记录（记录管理文档）：

类型 名称 IPv4 地址 代理状态 用途
A api ${ORIGIN_IP} DNS Only 形态 A
A a ${ORIGIN_IP} DNS Only 形态 B 应用 A
A c ${ORIGIN_IP} DNS Only 形态 B WebSocket 应用

TTL 可先使用 Auto。新部署可直接使用灰云；已有橙云记录可暂时保留，等第八节再切换。每个实际访问的子域都需要解析记录，通配符证书不会自动创建 DNS 记录。记录只填写 IP，不包含 :8443；没有公网 IPv6 就不要添加 AAAA。

3. 配置安全组

安全组与防火墙按以下范围配置：

端口 用途 开放范围
8443/tcp Nginx HTTPS 0.0.0.0/0
27500/tcp frps 控制通道（形态 B） 仅 frpc 出口 IP；无法固定时，依靠强 token 与 TLS
27022/tcp frps 代理端口（形态 B） 不对公网开放，并配置 proxyBindAddr
80 / 443 本方案不使用 无需放行

frpc 主动外连，因此内网机器无需入站规则。若使用公网 IPv6，需同步配置 Nginx 监听与 IPv6 防火墙。

八、确认 DNS Only 并验证解析

新部署如果在第三节已创建灰云记录，无需再次切换。已有橙云记录则在 Cloudflare 控制台选择对应域名，进入 DNS → Records，将 A 记录改为 DNS only（灰云）并确认指向 ${ORIGIN_IP}；需要回切时可提前调短 TTL。

如果此前使用橙云，还需关闭源站“仅允许 Cloudflare IP”的防火墙规则，以及 Authenticated Origin Pulls、Cloudflare Access 等边缘鉴权，否则直连会失败。

十、安全清单

  • 灰云会公开源站 IP：最小化安全组放行范围，并加固 SSH。
  • Cloudflare Token 仅授予必要权限，妥善保管并定期轮换。
  • 形态 B：frp token 使用强随机值、两端一致且不进仓库；控制端口尽量限制来源 IP。
  • 形态 B：proxyBindAddr 与安全组共同隔离 27022，并显式启用 frp TLS。
  • 形态 B：frpc 是单点，配置自动重启和定期探活。
  • 为 client_max_body_size 设置明确上限，避免无限上传。
